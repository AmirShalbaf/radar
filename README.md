## اجرا

دو فایل وابستگی از هم جدا هستند: `requirements.txt` فقط چیزی را دارد که
برای **اجرای** رادار لازم است، و گردش‌کارهای گیت‌هاب هم تنها همین را نصب
می‌کنند. `requirements-dev.txt` روی آن سوار می‌شود و ابزار **آزمون** را
اضافه می‌کند. اگر فقط رادار را اجرا می‌کنی، دومی را نصب نکن.

```bash
# اجرا
pip install -r requirements.txt

# توسعه و آزمون — شامل موارد بالا هم می‌شود
pip install -r requirements-dev.txt
python -m pytest tests/ -q

# اسکن
python radar_scan.py --preset all --venues okx,gate

# تحلیل عمیق
python radar_fetch3.py XLM --balance 800 --profile trade --venues okx,gate --macro-event 2026-07-29
```

## جمع‌آوری متن تحلیل‌گران — فقط محلی

`radar_intake.py` و `radar_digest.py` **فقط روی لپ‌تاپ** اجرا می‌شوند.
یوتیوب آی‌پی مرکز داده را می‌بندد، پس این مسیر روی گیت‌هاب اجرا نمی‌شود و
گردش‌کارها `requirements-intake.txt` را نصب نمی‌کنند.

```bash
pip install -r requirements-intake.txt
python radar_intake.py --dry-run --limit 2     # فقط فهرست، بی‌نوشتن
python radar_intake.py --limit 3               # اجرای واقعی
python radar_digest.py --all-roles
```

اگر یکی از کتابخانه‌ها نصب نباشد، اجرا از همان اول با نام بسته و کد خروج
۲ می‌ایستد — نه اینکه «۰ سند» بدهد.

منبعی که شکست خورد بقیه را متوقف نمی‌کند. نام و دلیلش در خروجی و بالای
`intake/INDEX.md` می‌آید، کنار منابع خاموش و دلیل خاموشی‌شان.

| کد خروج | یعنی |
|---|---|
| ۰ | همه منابع سالم |
| ۱ | هیچ منبعی انتخاب نشد |
| ۲ | وابستگی نصب نیست، یا `intake/.state.json` خراب است — هیچ چیز نوشته نشد |
| ۳ | دست‌کم یک منبع یا سند شکست خورد؛ بقیه کار کردند |

«زیرنویس ندارد» ویژگی ویدیو است و فقط گزارش می‌شود، نه شکست. **مسدودی**
یوتیوب شکست است و جدا گزارش می‌شود؛ اگر آی‌پی وی‌پی‌ان مثل مرکز داده بسته
شد، همین را می‌بینی. سنجش ۲۹ سپتامبر ۲۰۲۶ از پشت تونل لپ‌تاپ: هیچ مسدودی.

مقاله‌ای که متنش بریده است — خلاصه با «[…]»، پیش‌نمایش «Continue reading»،
یا کوتاه‌تر از ۱۵۰ کلمه — در شناسنامه و INDEX برچسب «متن ناقص» با دلیل
می‌گیرد، تا از متن بریده ادعا برداشته نشود.

**ffmpeg** فقط برای `--whisper` لازم است. برنامه جداست، نه بسته پایتون، و
روی لپ‌تاپ نصب نیست. ویسپر روی پردازنده لپ‌تاپ کند است؛ پیش‌فرض خاموش.

**`radar_intake_colab.ipynb` منسوخ است.** سلول دومش `git reset --hard` می‌زند
و هر خروجی ارسال‌نشده را پاک می‌کند، و سلول جمع‌آوری‌اش پیش‌فرض فقط یک منبع
دارد. حذفش تصمیم بعدی است — `STATE.md` بخش ۶.

## ویندوز — کدپیج کنسول

کنسول ویندوز پیش‌فرض کدپیج cp1256 دارد. هر اسکریپت رادار که فارسی چاپ کند،
بدون تنظیم UTF-8 با خطای `UnicodeEncodeError` می‌افتد. حتی یک نشانه ✅ در
خروجی آزمون‌ها کافی است که اجرا را نیمه‌کاره بشکند.

راه دائمی — متغیر محیطی کاربر را یک بار تنظیم کن:

```powershell
[Environment]::SetEnvironmentVariable("PYTHONUTF8", "1", "User")
```

بعد پنجره تازه باز کن. پنجره‌های باز مقدار قدیمی را نگه می‌دارند. بررسی:

```powershell
$env:PYTHONUTF8
```

راه موقت، فقط برای همین جلسه:

```powershell
$env:PYTHONUTF8 = "1"
```

`PYTHONUTF8=1` حالت UTF-8 مفسر را روشن می‌کند و هر دو سو را می‌پوشاند: هم
خروجی کنسول، هم خواندن و نوشتن فایل. جایگزین باریک‌تر `PYTHONIOENCODING=utf-8`
است که تنها جریان‌های ورودی و خروجی را درست می‌کند، نه فایل‌ها.

این همان کار باز شماره ۱۳ در `STATE.md` است.
